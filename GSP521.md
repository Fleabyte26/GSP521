# GSP521 – Cloud Security: Secure Software Delivery – Challenge Lab

## Known lab traps (read first)

1. The lab's cloudbuild.yaml is full of dollar-sign substitutions, which get mangled when copied. This tutorial writes the whole pipeline for you with no dollar signs: placeholders are filled in from your saved values, and the scan ID is read with backticks.
2. The Task 4 build is supposed to fail on a CRITICAL vulnerability. That failure is the checkpoint. Don't fix the Dockerfile until Task 4 is green.
3. Don't try to change IAM roles. The student account can't edit project IAM in this lab (you'd get "Policy update access denied"), and the roles the pipeline needs are already set up when the lab starts.
4. Submit builds in your lab region (`--region`), as the lab warns.
5. Big pastes get garbled in Cloud Shell. Paste one block at a time.
6. The Dockerfile starts from an old Debian 11 image, not a Python image. Just changing the FROM line breaks the build, so Task 5 replaces the whole Dockerfile.
7. The lab says the attestor name is vulnerability-attestor, but the signing step rejects the short name ("--attestor-project option is required"). The pipeline uses the full path projects/PROJECT/attestors/vulnerability-attestor.

## Setup (edit to match your lab)

Change the region on the first line to the REGION in your lab's Task 2 text.

```bash
echo us-east1 > ~/region
gcloud config get-value project > ~/project
gcloud projects describe `cat ~/project` --format="value(projectNumber)" > ~/projnum

```

## Task 3 – Binary Authorization

Block 1 – the attestor note:

```bash
cd ~/sample-app
cat > note.json <<EOF
{
  "name": "projects/`cat ~/project`/notes/vulnerability_note",
  "attestation": {
    "hint": {
      "human_readable_name": "Container Vulnerabilities attestation authority"
    }
  }
}
EOF
curl -s -X POST -H "Content-Type: application/json" -H "Authorization: Bearer `gcloud auth print-access-token`" \
  --data-binary @note.json "https://containeranalysis.googleapis.com/v1/projects/`cat ~/project`/notes/?noteId=vulnerability_note"
curl -s -H "Authorization: Bearer `gcloud auth print-access-token`" \
  "https://containeranalysis.googleapis.com/v1/projects/`cat ~/project`/notes/vulnerability_note"
```

Block 2 – the attestor:

```bash
gcloud container binauthz attestors create vulnerability-attestor \
  --attestation-authority-note=vulnerability_note --attestation-authority-note-project=`cat ~/project`
gcloud container binauthz attestors list
```

Block 3 – let Binary Authorization read the note:

```bash
cd ~/sample-app
cat > iam_request.json <<EOF
{
  "resource": "projects/`cat ~/project`/notes/vulnerability_note",
  "policy": {
    "bindings": [
      {
        "role": "roles/containeranalysis.notes.occurrences.viewer",
        "members": ["serviceAccount:service-`cat ~/projnum`@gcp-sa-binaryauthorization.iam.gserviceaccount.com"]
      }
    ]
  }
}
EOF
curl -s -X POST -H "Content-Type: application/json" -H "Authorization: Bearer `gcloud auth print-access-token`" \
  --data-binary @iam_request.json "https://containeranalysis.googleapis.com/v1/projects/`cat ~/project`/notes/vulnerability_note:setIamPolicy"
```

Block 4 – KMS key pair, linked to the attestor:

```bash
gcloud kms keyrings create binauthz-keys --location=global
gcloud kms keys create lab-key --keyring=binauthz-keys --location=global \
  --purpose=asymmetric-signing --default-algorithm=ec-sign-p256-sha256
gcloud beta container binauthz attestors public-keys add --attestor=vulnerability-attestor \
  --keyversion-project=`cat ~/project` --keyversion-location=global --keyversion-keyring=binauthz-keys \
  --keyversion-key=lab-key --keyversion=1
```

Block 5 – require attestations in the policy:

```bash
cd ~/sample-app
cat > policy.yaml <<EOF
defaultAdmissionRule:
  enforcementMode: ENFORCED_BLOCK_AND_AUDIT_LOG
  evaluationMode: REQUIRE_ATTESTATION
  requireAttestationsBy:
  - projects/`cat ~/project`/attestors/vulnerability-attestor
globalPolicyEvaluationMode: ENABLE
name: projects/`cat ~/project`/policy
EOF
gcloud container binauthz policy import policy.yaml
```

## Task 4 – Full pipeline with scanning and signing

Block 1 – build the custom attestation step (the lab's command):

```bash
cd ~/sample-app
git clone https://github.com/GoogleCloudPlatform/cloud-builders-community.git
cd cloud-builders-community/binauthz-attestation
gcloud builds submit . --config cloudbuild.yaml
cd ~/sample-app
rm -rf cloud-builders-community
```

If the push fails with "gcr.io repo does not exist", run `gcloud artifacts repositories create gcr.io --repository-format=docker --location=us` and then run Block 1 again.

Block 2a – first half of the pipeline:

```bash
cd ~/sample-app
cat > cloudbuild.yaml <<'EOF'
steps:
- id: "build"
  name: 'gcr.io/cloud-builders/docker'
  args: ['build', '-t', 'IMG_SCAN', '.']
  waitFor: ['-']

- id: "push"
  name: 'gcr.io/cloud-builders/docker'
  args: ['push', 'IMG_SCAN']

- id: scan
  name: 'gcr.io/cloud-builders/gcloud'
  entrypoint: 'bash'
  args:
  - '-c'
  - |
    (gcloud artifacts docker images scan \
    IMG_SCAN \
    --location us \
    --format="value(response.scan)") > /workspace/scan_id.txt

- id: severity check
  name: 'gcr.io/cloud-builders/gcloud'
  entrypoint: 'bash'
  args:
  - '-c'
  - |
      gcloud artifacts docker images list-vulnerabilities `cat /workspace/scan_id.txt` \
      --format="value(vulnerability.effectiveSeverity)" | if grep -Fxq CRITICAL; \
      then echo "Failed vulnerability check for CRITICAL level" && exit 1; else echo \
      "No CRITICAL vulnerability found, congrats !" && exit 0; fi

EOF
grep -c "severity check" cloudbuild.yaml
```

Block 2b – second half of the pipeline (appends to the same file):

```bash
cd ~/sample-app
cat >> cloudbuild.yaml <<'EOF'
- id: 'create-attestation'
  name: 'gcr.io/PROJECT_X/binauthz-attestation:latest'
  args:
    - '--artifact-url'
    - 'IMG_SCAN'
    - '--attestor'
    - 'projects/PROJECT_X/attestors/vulnerability-attestor'
    - '--keyversion'
    - 'KEY_VER'

- id: "push-to-prod"
  name: 'gcr.io/cloud-builders/docker'
  args:
    - 'tag'
    - 'IMG_SCAN'
    - 'IMG_PROD'
- id: "push-to-prod-final"
  name: 'gcr.io/cloud-builders/docker'
  args: ['push', 'IMG_PROD']

- id: 'deploy-to-cloud-run'
  name: 'gcr.io/cloud-builders/gcloud'
  entrypoint: 'bash'
  args:
  - '-c'
  - |
    gcloud run deploy auth-service --image=IMG_PROD \
    --binary-authorization=default --region=REGION_X --allow-unauthenticated

images:
  - IMG_SCAN
EOF
sed -i "s|IMG_SCAN|`cat ~/region`-docker.pkg.dev/`cat ~/project`/artifact-scanning-repo/sample-image|g" cloudbuild.yaml
sed -i "s|IMG_PROD|`cat ~/region`-docker.pkg.dev/`cat ~/project`/artifact-prod-repo/sample-image:latest|g" cloudbuild.yaml
sed -i "s|KEY_VER|projects/`cat ~/project`/locations/global/keyRings/binauthz-keys/cryptoKeys/lab-key/cryptoKeyVersions/1|g" cloudbuild.yaml
sed -i "s|REGION_X|`cat ~/region`|g; s|PROJECT_X|`cat ~/project`|g" cloudbuild.yaml
grep -nE "docker.pkg.dev|keyversion|KEY|gcr.io/qwik|region=" cloudbuild.yaml
```

Check that none of IMG_SCAN, IMG_PROD, KEY_VER, REGION_X or PROJECT_X are left in the output.

Block 3 – submit (this build should FAIL at "severity check"):

```bash
cd ~/sample-app
gcloud builds submit --region=`cat ~/region`
```

The output should end with "Failed vulnerability check for CRITICAL level". That's the expected result.

## Task 5 – Fix the vulnerability and redeploy

Block 1 – update the base image and dependencies:

The original Dockerfile starts from an old Debian 11 image, and its apt and sources.list lines only work on that image. On python:3.12-slim they would break the build, so this block replaces the whole Dockerfile. Pip is already included in the Python image.

```bash
cd ~/sample-app
cat > Dockerfile <<'EOF'
FROM python:3.12-slim

WORKDIR /app
COPY . ./

RUN pip3 install Flask==3.0.3
RUN pip3 install gunicorn==23.0.0
RUN pip3 install Werkzeug==3.0.4

CMD exec gunicorn --bind :8080 --workers 1 --threads 8 main:app
EOF
cat Dockerfile
```

The lab's original CMD binds to the PORT variable. Cloud Run's default port is 8080, so binding to 8080 directly does the same thing without a dollar sign.

Block 2 – rebuild (this time it should pass all steps and deploy):

```bash
cd ~/sample-app
gcloud builds submit --region=`cat ~/region`
```

Block 3 – open access for testing and check the app:

```bash
gcloud beta run services add-iam-policy-binding --region=`cat ~/region` --member=allUsers --role=roles/run.invoker auth-service
gcloud run services describe auth-service --region=`cat ~/region` --format="value(status.url)" > ~/url
cat ~/url
curl -s `cat ~/url`
```
